### ADR-001: Separation of LLM Routing from Agent Logic

**Date:** 2026-09-16
**Status:** Accepted
**Context:** Agents need to interact with multiple LLM providers (Gemini, Groq, OpenRouter) to ensure high availability and bypass free-tier rate limits. If agent logic handles fallback mechanisms directly, it becomes tightly coupled to specific LLM provider SDKs and complex to maintain.
**Decision:** All LLM calls will be routed through a central `LLMRouter` utility class. Agents will only define the prompt and expected structured output schema (Pydantic). The router will handle rate limit catching, fallback provider switching, and retry logic.
**Consequences:** Agents remain stateless and provider-agnostic. Adding a new provider only requires changes to the `LLMRouter`.

### ADR-002: In-Process Asyncio for MVP Job Management

**Date:** 2026-09-16
**Status:** Accepted
**Context:** Background processing is required for long-running research tasks to prevent HTTP timeouts. Typical solutions involve Celery or RabbitMQ.
**Decision:** For the MVP, we will use Python's built-in `asyncio.create_task` to manage background jobs in-process within FastAPI.
**Consequences:** This significantly reduces infrastructure complexity for the free-tier MVP. However, research jobs will be lost if the FastAPI server restarts or crashes. This is an accepted risk for Phase 1 and will be replaced by a robust task queue (Celery/Redis) in Phase 3.

### ADR-003: Supabase Service Role for Internal Writes

**Date:** 2026-09-16
**Status:** Accepted
**Context:** We need a way for the backend to insert data generated by agents (claims, evidence, agent logs) without requiring complex Row-Level Security (RLS) rules that allow users to write to these tables directly from the frontend.
**Decision:** The frontend will only use the Supabase Anon key, restricting it to RLS-gated reads. The FastAPI backend will use the Supabase Service Role key, bypassing RLS to safely execute internal inserts and updates.
**Consequences:** Ensures the frontend cannot manipulate research data. The Service Role Key must be kept strictly secure on the backend.

### ADR-004: Adopting "Sage Intelligence" Visual Direction

**Date:** 2026-09-16
**Status:** Accepted
**Context:** We need a cohesive aesthetic that signals trust and competence, contrary to typical "flashy" AI product designs.
**Decision:** The frontend will adhere to the "Sage Intelligence" visual direction: neutral palettes, serif headings, sans-serif bodies, and high data density over large illustrative elements.
**Consequences:** UI components will avoid heavy gradients, glowing borders, and pure dark modes, favoring subtle paper-like textures and sophisticated minimalism. This will guide all future frontend component implementation.
